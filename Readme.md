1. Project Overview and Business Problem
Setting a competitive listing price is a critical operational decision for short-term rental hosts entering the accommodation marketplace. This project develops an end-to-end Machine Learning regression pipeline to predict the advertised nightly price of an Airbnb listing using physical characteristics, structural features, host indicators, and aggregated review ratings.

Important Clarification:
This solution models the advertised asking price set by hosts. It does not reflect realized rental revenue, net profitability, or actual occupancy rates, as historical booking confirmations are not present in the supplied records.

2. Dataset and Currency Harmonization Strategy
The project leverages the Listings.csv dataset containing approximately 280,000 global records across 10 metropolitan markets.

- The Currency Challenge: Listing prices represent local currency amounts without an explicit ISO currency code. Combining prices across different cities without conversion introduces numerical distortion.
- Harmonization Strategy: To ensure mathematical validity and prevent target corruption, this project strictly scopes the predictive analysis to the Paris metropolitan market, calibrating all prices uniformly in Euros (EUR).

3. Data Preprocessing and Leakage Prevention
To guarantee production-grade generalization, the pipeline implements data leakage safeguards:
- Target Preprocessing: Non-positive and null prices were removed. Outlier trimming between the 1st and 99th percentiles mitigated extreme right-tail skewness.
- Train / Test Split: An 80/20 split (random_state=42) was conducted prior to any feature transformation or imputation.
- Pipeline Transformers:
  - Numeric features (accommodates, bedrooms, bathrooms, review_scores_rating): Imputed using the median learned strictly from the training split, followed by standard scaling.
  - Categorical features (room_type, property_type, host_is_superhost): Imputed with the most frequent category and encoded via One-Hot Encoding (handle_unknown='ignore').

8. Limitations and Recommendations
- No Dynamic Demand Factors: The model does not capture seasonal fluctuations, local events, or weekend pricing premiums.
- Geospatial Granularity: Incorporating specific arrondissements or distances to major landmarks would significantly improve pricing precision.
- Occupancy Disconnect: Recommendations serve as competitive asking price references, not as guarantees of bookings or actual revenue.
